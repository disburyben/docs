---
title: "Connecting Hermes to GitHub"
description: "Back up your skills, memory, and config to a private GitHub repo — the first thing every new agent should do"
---

This is the **first thing every new Hermes agent should do.** If the VPS gets corrupted, you
still have all your skills, memory, and config in GitHub. Just spin up a new Hermes and sync to
the repo.

## Setup workflow

<Steps>
  <Step title="Tell Hermes what you want">
    > "Set this up as a private GitHub repo. Do research and figure out how it works."
  </Step>
  <Step title="Let Hermes use its built-in skills">
    Hermes already ships with GitHub repo management and GitHub Auth skills.
  </Step>
  <Step title="Provide the details it asks for">
    Your GitHub username, repo name, commit identity, and personal access token.
  </Step>
  <Step title="Confirm the .gitignore">
    Hermes creates a `.gitignore` so secrets don't get pushed, even on private repos.
  </Step>
</Steps>

## Personal access token setup

In GitHub, go to **Settings → Developer settings → Personal access tokens**.

<AccordionGroup>
  <Accordion icon="key" title="First attempt: fine-grained token">
    Try a fine-grained token with **contents read/write** scope.
  </Accordion>
  <Accordion icon="key" title="If that fails: classic token">
    If the fine-grained token can't create repos, generate a **classic token** with full **repo**
    scope.
  </Accordion>
  <Accordion icon="clock" title="Set an expiration">
    Choose an expiration based on your use case — 30 days for testing, longer for permanent
    setups.
  </Accordion>
</AccordionGroup>

## How to save the API key safely

<Warning>
  **Don't paste API keys directly into the chat.** They live in conversation history forever. Use
  the Hermes config command instead.
</Warning>

<Steps>
  <Step title="Drop into the Docker shell">
    In the VPS, click **Open** to enter the chat, then hit **Ctrl+C** to exit Hermes chat into
    the Docker shell.
  </Step>
  <Step title="Set the token via config">
    ```bash
    hermes config set GITHUB_TOKEN <paste-token-here>
    ```
    This saves the token to `/opt/data/.env` inside the Docker container — never the conversation
    log.
  </Step>
  <Step title="Tell Hermes where it is">
    > "The new token is in the .env file as GITHUB_TOKEN."

    Hermes will pick it up automatically.
  </Step>
</Steps>

### Editing or deleting keys

If you need to delete or update a key, ask Hermes for the `nano` command to open the `.env` file.

<Warning>
  Make sure you're editing the `.env` **inside the Docker container**, not the root VPS `.env`.
</Warning>

- Use **Ctrl+O** then **Enter** to save.
- Use **Ctrl+X** to exit.
- If `nano` isn't installed, ask Hermes to install it or give you an alternative editing command.
